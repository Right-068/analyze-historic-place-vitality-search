# 空间、分类与匹配合同

## 空间

按 project.json 明确指定各图层身份，不靠 Id=0 或名称后缀决定图层。SHP/SHX/DBF/PRJ 缺失、空几何或无效 Polygon/MultiPolygon 阻断预检，不自动猜 CRS 或修补拓扑。内部坐标统一转换到 EPSG:4490；距离及面积使用研究区局部 UTM 米制投影。面积差异从几何实算，不用 DBF 的面积覆盖实际面。

core_only 只用核心；core_and_control 用核心与控制区并集。默认裁剪到指定总体面，环境协调区默认不含。输出保留原几何、裁剪几何、源 CRS、原面积、裁剪面积和差值。排除名单与期望数量是本任务配置，换地区需在运行前修改独立配置及数据。

POI 读取原生 GCJ-02 与提供的 cgcs2000_approx 两组坐标。近似坐标经迭代逆算校核，不改原坐标。默认10米一致性容限、20米边界带均不变。空间状态分为 inside、boundary_inside、boundary_outside、outside 及异常：文化 A/B 的边界候选允许检索，但 scope_adoption=boundary_candidate_not_confirmed_inside，不自动视为范围内。普通商业和辅助设施不因接近边界获得采集资格。每个关联面独立记录空间状态；面内环、多面及父子关系不改写。

## 候选分类

规则文件 assets/poi_filter_rules.json 版本化，检查全部 typecode。顺序：坐标/ID异常E → 明确范围外D → 附属设施名称C → 明确商业主体检查 → 自身文化功能A → 核心类别A → 独立影剧院/特色商业街类别B → 自身文化属性加兼容类别B → 辅助交通类别C → 其余D。商业主体有独立文化资料属性可为B，否则为D；位置型括号、尾附区域名称及区域别名不作为商户自身文化属性。普通商品类别不凭“工艺”字样纳入。parent_id 本身不构成 C 类理由。

明确独立文化馆、博物馆可以为父级景区子节点；仅“馆入口”等仍为辅助节点。名称文化线索只决定是否值得检索，并不宣称遗产法定身份。所有原始 POI 列保留在候选 CSV，附加规则版本、理由和层级。全量原件始终不动。

## 平台匹配

轻量过滤仅排除明确普通住宿、普通业务、非地点商业服务及缺名称记录。被实际查询发现、位置近或同研究范围的文化候选进入模型，不要求名称相同，不因缺景点接口拒绝语义判断。模型读取程序已计算的空间事实，不自行猜测CRS或重写边界。关系结果随后执行sight类型、数字poiId/sight ID、详情链接、城市及各关系空间一致性检查；无接口的表达仅保留映射，不授权采集：
- same_as沿用原有点位距离条件与门牌冲突检查；
- represents_area要求区域实体和范围内/边界附近锚点；part_of要求内部位置；related_to在模型确认给定资料关联后还须共同研究区或近点佐证。它们不套用“同一门牌”条件，也不扩大既有距离或边界带。未知CRS时点位只可用既有明确地址佐证，不能择优坐标。

默认平台 CRS unknown。解析器保留原始坐标字段、接口来源及可选 CRS 元数据，不把未说明的数值当作官方坐标声明。任务内先用名称、城市和门牌独立对应且候选唯一的地点建立锚点，按不同街道门牌去重；至少3处全部支持同一个距离200米内的坐标解释、其他解释不同时成立，才形成当前任务/城市/接口经验校准。两种残差及原件哈希输出到 matching/坐标解释校准.json。未知或矛盾状态不取最有利距离，仍需独立地址证据；所有解释都远离则拒绝。明确 CRS 配置仅供启动前有依据的选择。

常规实体默认最多4个查询（上限6）；所有 L1 区域实体最多6条（上限8），资料正式名称后优先安排受控区域旅游表达和城市限定，再补资料别名。具体名称来源和关联判定以 entity-resolution.md 为准。不能删展区等身份限定词，不能自由造可信别名；同响应候选保留全部 query_id 和 raw_sha256。扩展发现不等于采用，同一地点断言遇同街门牌冲突不授权采集。有限预算不是减少研究对象。

空间事实由程序计算并作为关系模型上下文；采集许可仍由程序独立核验，模型关系有效也可能被阻止。低置信度转宿主，仍不足则保留不采集，不外推未给的历史。旧poi_match.py只用于坐标校准及兼容测试，不是平台表达结论；manual_mappings不覆盖模型。重复原生身份保留查询来源，冲突不强制合并；平台按ID只采集一次。没有父级不是冲突，矛盾父级不能支持肯定推断。

## 采集与恢复

公开 search 与 comment 接口沿用（1）版。请求限速、超时与重试均有限；HTTP成功、业务有效、结构有效、分页结束和地点完整分别判断。总数缺失不作0，空页早于已知总数、重复页、总数变化或页数上限均记部分完成。

每次 HTTP 响应先原样写内容寻址文件，再持久化尝试记录，最后校验结构后标 success。错误响应留存但不生成评论。重启复用哈希相符的成功响应；HTTP200 已保存但此前解析失败/提交中断时先重解析，仍结构异常则留错不反复请求；无可用响应的临时失败可以有限重试。原件损坏不重抓覆盖。受限状态锁定来源，不能重启清除。

items=null 只在业务成功、明确 totalCount=0 且 totalCollapseCount=0、无隐藏数量矛盾时规范为空数组。两种不分星级排序确认一致空结果后停止其他切片并记 interface_empty；确认不足/矛盾为 partial，不称全平台零评论。展示总量与接口总量分列，差额含义不擅自推断。

默认首先尝试全部星级分页；取得明确总数后不做无意义重复请求。未取得完整数据时才按既有星级/排序切片继续；访问限制一旦出现，所有切片停止。这不是用排序规避平台限制。相同评论的全部出现保存，表格以平台+POI+评论ID去重。后出现的不同原文版本留在出现记录中，不将平台正常编辑当成本地哈希损坏。
